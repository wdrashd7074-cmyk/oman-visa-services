# خدمات تأشيرات عُمان — حزمة بداية

واجهة عربية + API لاستقبال الطلبات + قاعدة PostgreSQL + لوحة تحكم إدارية + روابط واتساب للمتابعة.

## قبل الاستخدام

هذه حزمة بداية تقنية وليست خدمة مستضافة بعد. يلزم إعداد الاستضافة وقاعدة البيانات والأسرار والاختبار قبل نشرها للعملاء. لا ترفع وثائق جوازات السفر أو صور الهويات في النسخة الحالية؛ لم يتم بناء مسار رفع ملفات آمن.

## المتطلبات

- Node.js 20 أو أحدث.
- استضافة تدعم تشغيل تطبيق Node.js باستمرار.
- قاعدة بيانات PostgreSQL مُدارة، ويفضل أن تكون لدى مزود الاستضافة نفسه.
- نطاق فرعي مجاني من مزود الاستضافة، أو نطاق خاص لاحقًا.
- HTTPS/TLS مفعّل.
- حساب بريد/وسيلة اتصال لخدمة العملاء وسياسة خصوصية منشورة.

## التشغيل محليًا

1. ثبّت Node.js.
2. انسخ `.env.example` إلى `.env` واملأ القيم.
3. أنشئ قاعدة PostgreSQL وقاعدة بيانات باسم `oman_visa_services`.
4. في التطوير المحلي فقط، اجعل `DATABASE_SSL=false` إذا كانت قاعدة البيانات المحلية لا تستخدم TLS.
5. شغّل `npm install` ثم `npm start`.
6. افتح `http://localhost:3000`.

لا تستخدم بيانات `.env.example` كما هي. أنشئ `SESSION_SECRET` عشوائيًا طويلًا، واستخدم كلمة مرور إدارية فريدة. لا ترفع `.env` إلى Git أو ترسله عبر المحادثات.

## النشر على رابط فرعي مجاني

1. أنشئ تطبيق Node.js لدى مزود استضافة يدعم Node 20+.
2. ارفع ملفات المشروع إلى مستودع خاص أو ارفعها مباشرة حسب تعليمات المزود.
3. أنشئ قاعدة PostgreSQL مُدارة وفعّل TLS.
4. أضف متغيرات البيئة من لوحة الاستضافة: `NODE_ENV=production`, `PUBLIC_ORIGIN` بعنوان الموقع النهائي، `DATABASE_URL`, `DATABASE_SSL=true`, `SESSION_SECRET`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`.
5. تأكد أن مزود قاعدة البيانات يدعم TLS بسلسلة شهادات موثوقة؛ إن كان يتطلب إعدادًا مختلفًا فلا تغيّر `rejectUnauthorized` إلى `false` دون مراجعة إعداداته الرسمية.
6. فعّل HTTPS للنطاق الفرعي، ثم اختبر إرسال الطلب، دخوله إلى قاعدة البيانات، تسجيل الدخول الإداري، تغيير الحالة، تسجيل الخروج، وحدود محاولات الدخول.
7. احتفظ بنسخ احتياطية مشفرة واختبر استعادتها. راقب الأخطاء دون تسجيل محتوى الطلبات أو بيانات شخصية في السجلات.

## واجهات API

- `POST /api/requests` — استقبال طلب جديد.
- `POST /api/admin/login` — تسجيل دخول الإدارة.
- `GET /api/admin/requests` — عرض أحدث 300 طلب بعد تسجيل الدخول.
- `PATCH /api/admin/requests/:id/status` — تغيير حالة طلب.
- `POST /api/admin/logout` — تسجيل الخروج.
- `GET /api/health` — فحص اتصال قاعدة البيانات.

## واتساب

لوحة الإدارة تفتح محادثة `wa.me` باستخدام رقم الهاتف الذي أدخله العميل. رقم واتساب الخاص بالنشاط غير مُضمّن حتى الآن؛ يلزم تأكيد الرقم الكامل بصيغة دولية من دون `+` أو مسافات، مثل `249XXXXXXXXX`. لا يوجد إرسال تلقائي للرسائل في هذه الحزمة.

## متطلبات أمنية قبل استقبال الجمهور

- غيّر كلمة مرور الإدارة إلى كلمة قوية وفريدة، وفعّل MFA من مزود الهوية إذا أضفت تسجيل دخولًا مؤسسيًا.
- قيّد صلاحيات قاعدة البيانات وفعّل TLS، والنسخ الاحتياطي، ومراقبة الوصول.
- أضف سياسة خصوصية وموافقة واضحة، ومدة احتفاظ وحذف للبيانات، وطريقة تواصل للشكاوى.
- لا تجمع معلومات أكثر من اللازم. لا تجمع بيانات جواز السفر أو وثائق الهوية عبر النموذج الحالي.
- أضف حماية إضافية ضد الرسائل المزعجة، ومراجعة أمنية مستقلة، واختبار استعادة النسخ الاحتياطية.
- إعدادات الجلسة الحالية مناسبة كبداية، لكنها لا تغني عن مراجعة أمنية قبل الاستخدام الإنتاجي.
- تحقق من المتطلبات الرسمية للتأشيرات عبر الجهات العُمانية المختصة. الموقع خدمة مستقلة ولا يصدر تأشيرات ولا يضمن الموافقة.
